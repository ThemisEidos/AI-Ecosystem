# Reporting Workflow Standards

## Purpose

This document defines the standard process for creating analytical reports inside the AI Ecosystem.

The workflow is intended to produce reports that are accurate, clear, defensible, evidence based, and professionally written.

## Core Reporting Principle

> Source material stays raw.  
> Analysis becomes structured.  
> Final reports become polished.

AI may improve structure, clarity, and analysis. AI may not create facts.

## Standard Report Lifecycle

```text
Capture → Normalize → Analyze → Draft → Review → Finalize → Archive
```

## COOPER Usage

- Open Workshop may be used for sanitized report drafting, rewriting, and summary work.
- Private Workshop must be used for restricted or local-only report work.
- Category 2 source material must remain local unless it has been sanitized first.

Storage rules:

- Open Workshop may write drafts to Obsidian or Project Workspace with approval.
- Private Workshop may write only to the Restricted DMZ Workspace.
- Private Workshop cannot write to Obsidian unless the human creates a sanitized Category 1 export and switches to Open Workshop.
- Secure Vault and StandardNotes are outside COOPER automation scope.

## 1. Capture

Capture preserves raw information before it is cleaned or rewritten.

Rules:

- preserve raw notes before editing
- separate facts from assumptions
- label source material clearly
- preserve uncertainty
- do not allow AI to invent missing details

## 2. Normalize

Normalization turns raw material into a consistent working format.

Typical outputs:

- normalized notes
- timeline
- evidence index
- open questions
- source material index

## 3. Analyze

Analysis identifies patterns, gaps, risks, causes, and recommendations.

Rules:

- separate confirmed observations from judgment
- identify supporting evidence
- label assumptions clearly
- avoid unsupported certainty

## 4. Draft

Drafting converts analysis into a structured report.

Typical report components:

- title
- executive summary
- purpose
- scope
- methodology
- findings
- analysis
- recommendations
- limitations
- appendices

## 5. Review

Review ensures the report is accurate, clear, and ready for release.

Check for:

- accuracy
- clarity
- logic
- source support
- missing facts
- unsupported claims
- inconsistent timelines
- sensitive information

## 6. Finalize

Final products may include:

- Word document
- PDF
- PowerPoint briefing
- one-page summary
- appendix package

Store the final version separately from drafts.

## 7. Archive and Lessons Learned

Archive:

- final report
- timeline
- evidence index
- key drafts
- review notes
- lessons learned

## Evidence Standards

Evidence labels:

- Direct Observation
- Documented Record
- Photo or Screenshot
- Log Output
- Interview Statement
- Tool Result
- Open Source Reference
- Analyst Inference
- Assumption
- Unknown

## Recommendation Standard

A useful recommendation should identify:

- what should change
- why it matters
- priority
- expected effect
- any dependency or limitation

## Security and Sensitivity Rules

Do not store the following in a normal vault unless the storage environment is protected:

- passwords
- API keys
- client-sensitive raw data
- personally identifying information
- legally sensitive material
- unredacted reports
- restricted logs

Recommended handling:

- General reporting standards -> Obsidian
- Reusable templates -> Obsidian
- Sanitized notes -> Obsidian
- Sensitive raw material -> Restricted DMZ Workspace
- Long-term protected material -> Secure Vault after human review
- Credentials and keys -> password manager

## Final Standard

The reporting workflow is:

```text
Capture → Normalize → Analyze → Draft → Review → Finalize → Archive
```

Supported by:

- TCREI for structure
- AI for organization and review
- Human author for judgment and accountability
